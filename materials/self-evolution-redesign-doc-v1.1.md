## 1. 现状 IA 盘点（基线 cc1eb65c）

现状为**单页 8 Tab**：`apps/web/app/[workspaceSlug]/(dashboard)/self-evolution/page.tsx` → `packages/views/self-evolution/components/self-evolution-page.tsx`，`useState("quality")` 控制激活页签，**无子路由**（刷新/分享即丢状态，无法深链）。

| Tab（现状名） | 承载数据 | 现有操作 | 主要问题 |
| --- | --- | --- | --- |
| 总览 | 6 个只读区块卡：版本分布 / 质量度量 / 题库测验 / 立法提案（刻意未接线，RUYI-284 边界）/ 知识库 / 技能演进 | 无（纯镜头） | 无可行动项；异常（如 LLM 未配置）在总览不可见 |
| 质量（默认页签） | 主体×时间窗的四维指标、版本时间线（≤2 版对比）、困惑度分档 | 选主体、切窗口、版本对比、打开困惑度 Sheet | **降级数据源只以页脚 Tooltip 行出现**（`degraded-*`），不可行动、无状态闭环 |
| 版本 | 各层级 prompt 版本时间线 | 查看版本 | 与质量页时间线割裂，无统一入口语义 |
| 题库测验 | 主体判读卡（QuizReading）+ 判读面板（owner）+ 题库（owner 可编辑，admin 刻意排除） | 编辑题库、看判读 | 结构尚可，仅随导航整体迁移 |
| Skill | Select 下拉当 Skill 选择器；版本历史+用量+版本对比+使用组/对照组+版本事件+最近使用纵向堆叠；版本详情 Sheet；CatalogDiscoveries 待导入发现；「管理」外链 /skills | 切换 Skill、看版本、导入发现 | **下拉当列表**；单 Skill 全信息无层次；发现与已管理混在一页 |
| 立法提案 | 提案池（RUYI-305 模型替换中） | 审阅提案 | 随导航迁移，本期不重组其数据模型 |
| 每日总复盘 | 任务开关（enabled / include_in_review / window_days）+ 运行记录（失败原因内联） | 保存配置、立即运行、看记录 | **LLM 未配置时无 UI 配置入口**，失败记录只报 `MULTICA_LLM_API_KEY / MULTICA_LLM_BASE_URL 为空`（RUYI-552 缺陷面） |
| 知识库 | 目录卡片区（注册/扫描/注销/采纳，owner-only）+ 条目表 | 注册/扫描/注销目录、采纳条目 | **目录卡片铺满首屏**、条目沉底；目录无详情、扫描失败不可追溯；**「添加外部来源」折叠在页底 ghost「▸ 高级」** |

总览从「纯镜头」升级为**可行动驾驶舱**：顶部新增「需要关注」区（仅显示可行动项，处理后自动消失）——模型服务未配置 → 「去配置」；运行时发现待导入 → 「查看」。下方保留 6 张摘要卡，每卡带「查看 →」跳对应子页。只读边界不变：总览树内不出现任何写控件（延续 RUYI-284 的组件测试约定）。

- 外部来源分段：独立表格（来源/路径/类型/健康/条目/最近扫描/操作），异常行（如 Permission denied）在段内给出闭环，并提供链接跳转「知识目录」分段。

### 2.4 技能演进页（图 5–6）

- 两分段：**已管理 Skill / 待导入发现**。列表行：名称+描述、来源徽标、最新版本、30 天调用+重试率、中位 token+±% 徽标、最近使用。
- 行点击进**详情路由页**（图 6）：详情头（说明/来源/最新版本 + 「管理与配置 →」外链）；版本历史列（版本、来源如「立法提案 #12」、期间调用量）；版本点击进版本抽屉（内容 + 与上一版 diff + 按版本用量 + 「恢复为此版本」）；右侧版本成本对比（v3→v4）与使用组 vs 对照组表（保留现状样本门槛语义：样本 ≥5 才比较，不足显示「样本不足」）。
- **配置边界**：Skill 内容编辑与智能体指派仍归既有 `/skills` 管理页（避免双配置面）；自进化详情页只做展示与演进动作（恢复/导入/对比）并显式外链。

### 2.5 质量度量页 · 数据源状态闭环（图 7）

- 页首新增「数据源状态」区：评分模型、Langfuse 各一张 `DataSourceStatusCard`。
- **四态闭环规范**（每一态必须同时回答四段；v1.1 修订：绿/红两态的原因文案按生效来源区分，边界见下方决策段）：

| 状态 | 原因（示例文案） | 影响 | 操作（可行动） |
| --- | --- | --- | --- |
| 未配置（灰点） | 未检测到任何来源的配置 | 相关维度无数据，页面进引导态 | 「去配置」（模块级直达；系统级给部署说明） |
| 配置错误（红点） | 连通性校验失败：401（凭据无效或过期）；**仅模块配置来源可进入此态** | 保留最近一次成功数据并标注时间，不显示空态 | 查看错误详情 / 重新校验 |
| 已配置可用（绿点） | 模块配置来源：连通性校验通过（含最近校验时间）；部署默认来源：检测到部署注入的默认值（**未主动校验**）；均带生效来源标注 | 全维度正常 | 查看配置 / 调整 |
| 功能关闭（琥珀点） | 来源健康但被工作区开关停用 | 停止采集新数据，历史保留可查 | 「启用」（跳模块配置页开关） |

- **env 来源语义边界（v1.1 决策，方案 A）**：「配置错误」态仅由**连通性校验动作**产生，而校验只发生在模块配置来源（保存时强制校验 + 状态卡「重新校验」）；部署 env 默认来源不存在任何校验动作（部署侧注入，现状亦无健康探测作业），故 **env 来源只承诺三态：未配置 / 已配置 / 功能关闭，不承诺「配置错误」**。env 来源处于「已配置」时，原因文案固定为「检测到部署注入的默认值（未主动校验）」，禁止出现「校验通过」字样。运行时失败一律由各自承载面呈现——复盘走运行记录（失败原因 + 重跑），质量评分走降级横幅与数据标注——**不在数据源状态卡上把运行失败冒充为「配置错误」**。淘汰方案 B（以最近一次运行失败被动回传充任错误态）的理由：B 需要新增「运行失败 → 配置错误」的错误分类判定（超时/抖动算不算配置错误？），误判面大，且与「状态卡只回答配置健康、运行健康由运行记录承载」的职责边界冲突；运行失败本已有闭环承载面，B 不提供增量价值。图 7 即模块配置来源的示例稿，与本边界不冲突，**不需改图**。本边界在 §8.1 造态矩阵中以负向断言同步承载（走查 #23）。
- 降级存在时度量区顶部出蓝色提示横幅（「部分来源降级…」+ 「查看数据源状态」锚点）——**禁止现状的 Tooltip 尾注式呈现**。
- 质量页其余主体结构（主体选择、时间窗、维度卡、版本时间线、对比弹窗、困惑度 Sheet）维持现状信息模型，仅随新导航迁移。

## 3. 配置域归属结论（本设计的核心判断）

先给后端事实（基线代码核查）：

- **评分模型**：`server/pkg/promptquality` 直接使用平台 LLM 客户端（`h.LLM.Enabled()`，prompt_quality.go:166）；无独立凭据。
- **复盘 LLM**：`server/internal/retrospective/runner.go` 使用同一 `pkg/llm` 部署级客户端；未启用时运行失败并报 `MULTICA_LLM_API_KEY / MULTICA_LLM_BASE_URL 为空`。
- **Langfuse**：`DescribeSources`/`LangfuseExportEnabled()` 只读部署环境变量（`LANGFUSE_PUBLIC_KEY`/`LANGFUSE_SECRET_KEY`，sources.go:98-99），export-only（「已配置，未被调用」），无工作区维度。

结论：

| 配置对象 | 归属 | 理由 |
| --- | --- | --- |
| 复盘 LLM + 评分模型 | **自进化模块级**（工作区 DB 配置，仿 retrospective config 既有模式） | 二者共用同一 `pkg/llm` 客户端类型、同属本模块的可用性前提，按工作区覆盖是真实需求（不同工作区接不同网关/模型）；env 作为部署默认回落 |
| Langfuse | **系统级（实例部署域，管理员）** | 实例级导出通道，凭据由部署注入、无工作区维度，工作区 UI 给开关就是假配置；质量页只放**只读状态卡** + 「复制部署配置说明」 |

**生效来源优先级与展示**：`模块配置 > 部署环境变量默认 > 未配置（不可用态）`；UI 用中性灰 `ConfigSourceBadge` 三态标注（生效来源：模块配置 / 生效来源：部署默认 / 系统级·实例部署注入），任何状态卡与配置卡都必须带生效来源徽标。

**模型服务的卡面建议**：模块配置页用**一张「模型服务」卡**（Base URL / API Key / 模型 + 校验），卡内标注两个消费方（质量评分、每日总复盘）各自的启用状态——因为二者共享同一客户端，分两卡会诱导重复凭据与不一致。

### 3.1 每日总复盘 LLM 配置流（图 8）

- 复盘页 = 任务设置卡（现状三开关不动）+ **LLM 配置卡** + 运行记录。
- LLM 配置卡：生效来源徽标 + Base URL（明文可编辑，非机密）+ **API Key 掩码 `••••`（保存后加密存储、不再回显，仅可更换；留空=保持现有）** + 模型 + 最近校验时间；「恢复部署默认」清工作区覆盖回落 env，二次确认。
- 配置弹窗：保存前强制连通性校验，失败不允许保存并给出具体错误（超时/401/模型不可用）。
- **运行记录行字段规格（v1.1 补，不改图 8 布局）**：触发方式（手动「立即运行」/ 定时）、开始时间与耗时、状态（成功/失败/运行中）、**本次运行所用模型 + 生效来源徽标（模块配置/部署默认）**、失败原因（失败时内联，含错误分类：凭据无效/连接失败/模型不可用/其他）、行内操作（失败可「重跑」）。其中「所用模型 + 生效来源」是「立即运行读取 UI 已保存配置」的**可观察载体**——它使「徽标显示对、运行实际用错」一类缺陷（RUYI-552 的镜像面）在验收时可判定，对应走查 #22。
- 失败运行记录保留原因与时间线，配置生效后提供「重跑」——失败不再是死胡同。RUYI-552 修缺陷本体，与本配置 UI 互补不重叠。

## 4. 主要用户路径

1. **配置接通**：总览「需要关注：模型服务未配置」→ 去配置（模块配置页）→ 校验并保存 → 返回质量页看状态卡转绿 → 复盘页 LLM 卡同步生效。
2. **知识沉淀**：知识库 → ＋添加外部来源 → 注册目录 → 扫描 → 条目分段审阅 → 条目抽屉 → 采纳进知识总库。
3. **目录运维**：知识目录/外部来源分段 → 异常行/详情抽屉看扫描历史与原因 → 重新扫描 / 注销（二次确认）。
4. **技能演进**：技能演进列表 → 行进详情 → 版本抽屉看 diff 与用量 → 恢复此版本 / 打开管理与配置；待导入发现 → 导入。
5. **质量诊断**：质量度量 → 选主体/窗口 → 维度卡 → 版本时间线对比 → 数据源异常时状态卡直达修复。
6. **复盘运维**：每日总复盘 → 配置 LLM → 立即运行一次 / 失败记录重跑。

## 5. 组件与状态规范

## 7. 给顾小鱼的实现注意事项

1. **路由**：子路由注册进 `paths` + AppLink；`self-evolution-page.tsx` 的 Tabs 换 `SeSubNav`；主体选择等次要状态可继续用 query 参数，不必急于 path 参数化。
2. **后端依赖（需开发排期，不在本设计内）**：① 工作区级「模型服务」配置存储 + 连通性校验端点（覆盖质量评分与复盘 LLM 两个消费方）；② 数据源状态端点扩展（现状 `DescribeSources` 布尔级，需带错误详情与最近校验时间才能撑起四态闭环；v1.1 按方案 A 收窄：错误详情与最近校验时间仅模块配置来源要求，env 来源只需透出「存在部署默认值」与生效来源，不要求校验数据）；③ Langfuse 只读状态透出。
3. **兼容与迁移顺序建议**：先导航框架+知识库（改动最大、收益最直观）→ 技能演进 → 质量+模块配置 → 复盘 LLM 卡 → 总览收口。现有 testid（`degraded-*`、`retrospective-*`、`overview-*` 等）尽量保留映射，降级重构时同步更新测试；旧 8 Tab 页签条本身不保留（走查 #17 负向断言）。
4. **安全**：`SecretField` 走既有加密凭据机制；任何日志、错误信息、接口响应不得回显 Key 明文；「复制部署配置说明」只输出变量名与占位符，不含值。
5. **RUYI-552 边界**：552 修「复盘 LLM 配置了但失败」的缺陷本体；本设计提供配置入口与状态呈现，合流时以后端实现为准对接字段，设计不重复修码。
6. **提案页（立法提案）**：RUYI-305 模型替换仍在飞，本期只迁移不重组；总览提案摘要卡维持「待模型替换」占位语义。

### 8.1 四态造态矩阵（v1.1 新增 · 验收取证方法）

| 状态 | 前置条件 | 注入通道（QA 槽位可执行） | 预期观察点 |
| --- | --- | --- | --- |
| 未配置（灰） | 工作区开关开启；无模块配置覆盖且无部署 env 默认 | 清空槽位 env 的 `MULTICA_LLM_*` 并重启服务；UI「恢复部署默认」清工作区覆盖 | 状态卡灰点「未配置」；总览「需要关注」出现「模型服务未配置 → 去配置」；复盘「立即运行」给「去配置」引导而非裸报错 |
| 已配置可用（绿） | 生效配置连通可用 | 本地 stub 网关返回有效响应（依赖 §7.2① 校验端点实现）；经 UI 保存（徽标=模块配置）或注入有效 env 默认（徽标=部署默认） | 绿点 + 生效来源徽标；模块配置来源含最近校验时间；部署默认来源含「未主动校验」文案 |
| 配置错误（红） | 生效来源=模块配置，且校验曾通过、事后失效 | 保存有效配置（stub 校验通过）→ 将 stub 改为返回 401/超时 → 状态卡点「重新校验」 | 红点 + 具体错误（如 401 凭据无效）；保留最近成功数据并标注时间；「查看错误详情/重新校验」可用 |
| 功能关闭（琥珀） | 模块配置页关闭对应消费方开关 | UI 开关停用即可，无需动数据 | 琥珀点「功能关闭」+「启用」直达；历史数据保留可查 |

**矩阵边界断言（与 §2.5 方案 A 一致）**：「配置错误」态只有矩阵第 3 行**一条**造态通道（模块配置来源事后失效 + 重新校验）。评审指出的两条候选造态路径处置：①「有效配置事后失效」——采用，为唯一通道；②「部署 env 默认值本身无效」——按方案 A **不产生**配置错误态（env 来源只承诺三态）。若 QA 需在 env 通道验证无效默认值的表现，预期观察点为：状态卡显示绿点「已配置（未主动校验）」，实际失败由运行记录（含失败原因与重跑）或质量页降级横幅承载，并给出「去配置」引导。
