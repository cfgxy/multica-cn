# ADR 010：版本化跨空间授权与受限事务回执（RUYI-844）

- 日期：2026年10月21日
- 状态：accepted（技术架构评审通过；补充并收紧 ADR 006，不扩展为通用跨空间代理）
- 关联：RUYI-844、Draft PR #465、ADR 006

## 1. 背景

ADR 006 已提供分空间授权请求、双 Owner 审批、执行审计和最小来源投影。RUYI-844 暴露出单一提示词写操作不足以覆盖被批准的事务类别，且“批准”与“副作用已发生”必须由不同状态表示。本文记录授权请求、执行器、回执和客户端可见性的进一步约束。

## 2. 不可变授权规范

每个请求在首个审批发生前固化版本化规范：`kind`、canonical scope、规范化参数及内容 digest、来源/目标 workspace、来源 Issue/task、过期时间和可公开摘要。规范一经创建不可变；创建响应和两侧投影不得提供修改入口。两侧审批、最终 claim 和执行器均重新计算并比较相同 digest；不一致时 fail closed 并审计，不执行。

双 Owner 审批仍为跨空间写入前置条件。拒绝、撤销和到期均终止待执行请求。执行只能通过唯一、持久化的 claim 进入；重复审批或并发请求不得产生第二次副作用。通用目标空间浏览、成员资格或可复用凭据不属于授权能力。

## 3. 白名单事务边界

所有执行动作由服务端登记、参数化的处理器实现，不接受 shell/命令拼接。当前允许三类：

1. 白名单 CLI：请求只含服务端登记的处理器 ID 和已验证参数；不能提交任意可执行文件或命令文本。
2. 受限脚本：执行定义固定可读来源/内容及其 hash、解释器和参数，必须在受限沙箱中运行；日志先脱敏再持久化或返回。没有可证明的沙箱能力时拒绝执行。
3. 单一事项建单：仅创建一个范围明确的目标空间 Issue，以请求幂等键创建并进入 `in_progress`；在该 Issue 达到 Done 后生成完成回执。该单 Issue 限制不适用于其他事务。

`project_prompt_sync` 是白名单参数化事务，允许请求中经审批的显式多项目集合。目标项目全量预校验后原子写入；失败时整批回滚。禁止修改 iData。

## 4. 副作用与回执

回执采用结构化、逐步骤结果，并明确副作用状态：`no_side_effect`（已确认无副作用）、`completed`（已确认完成）、`unknown`（结果待核实）。执行摘要按请求方、目标 Owner、无权限读取者分层；目标内容、脚本正文/参数秘密、原始日志及可复用凭据不跨空间返回。

事务可中断时，只有能证明没有副作用的失败可标记 `no_side_effect`。任何中断或未知副作用都标记 `unknown`，不可原地重试；必须新建请求并重新审批。脚本/Issue 事务可以保留已完成步骤事实，但不得自动重放。提示词同步按原子语义全批回滚。

## 5. 兼容与 UI 契约

决策中心和 Issue 授权卡须显示事务预览、双 Owner 审批时间线、执行中状态、逐步骤结果、失败/待核实状态及撤销/过期/越范围/重复执行结果。来源空间只读取最小投影。Web/Desktop 与 Mobile 对事务种类、权限、状态和回执字段保持一致；窄屏允许采用纵向详情布局。关键操作、状态变化和错误须可键盘访问并有屏幕阅读器语义。

## 6. 安全与验证边界

没有受限脚本沙箱或可持久化执行 claim 时，相关执行必须 fail closed，不得以进程内锁或“已批准”状态替代。新增授权类型只能逐项登记、定义参数 schema、回执白名单和测试；不得提供通用跨空间执行接口。验证至少覆盖批准/拒绝/撤销/过期/越范围/并发幂等、各类型正常/失败语义、跨空间字段隔离及三端关键无障碍状态。
