# ADR-009：受控文件读取的预置禁读策略与平台管理配置

| 属性 | 值 |
| --- | --- |
| 创建日期 | 2026-10-18 |
| 状态 | accepted |
| 来源 | RUYI-793；Owner 2026-10-18 指定复用并改写 `977_mcp_file_access` |

## 背景与范围

原受控文件读取链路已有硬编码敏感路径检查，但没有可维护的平台策略。新增平台级持久化拒绝规则，覆盖三个 MCP 文件工具、直接 API、本机与登记远端。该策略不是宿主机沙箱，不限制任意 Shell 或第三方程序。

## 决策

- 配置由平台超级管理员通过共享 Web/Desktop 管理页维护；后端 API 独立执行超级管理员和真人会话校验，并使用版本号拒绝并发覆盖。
- 默认规则覆盖 SSH/GPG、云凭据、Kubernetes、容器与包管理凭据、环境文件、私钥和常见 AI 客户端认证。路径模式只支持有界 glob，不执行正则或表达式。
- 请求入口检查规范化路径；daemon 检查最终解析路径及分页目录项。daemon 必须声明 `file-read-policy-v1`，服务端才会派发读取。策略缺失、无效或旧 daemon 均失败关闭。
- 每次派发携带策略版本和规则；完成回执必须携带相同版本。数据库条件更新再次校验当前版本，避免策略更新后释放由旧策略产生的文件结果。
- 审计只记录动作、操作者、规则数量和版本，不记录规则路径、文件内容或凭据。访问拒绝沿用既有文件操作/MCP invocation 审计关联。

## 迁移生命周期与 hp-server 已执行库升级

Owner 明确授权复用并改写 `977_mcp_file_access`。该迁移改为幂等 DDL，旧版已建表不重建、不清理数据；策略表仅在尚无配置行时写入默认规则。并发索引仍保留各自独立 migration 文件，`978` 不变。

迁移器按 `schema_migrations.version` 跳过已登记版本。因此仅替换文件或仅修改账本都不能完成升级。hp-server 执行必须由获授权运维在维护窗口按以下顺序完成，并保留升级前后核验：

1. 备份数据库，并只读核对 `977_mcp_file_access` 登记状态、原三张对象的结构及既有行数。
2. 删除 `schema_migrations` 中且仅中 `977_mcp_file_access` 这一条版本记录；不删除其他 977 并行索引迁移记录。
3. 运行仓库 `make migrate-up`。重写后的 977 使用 `IF NOT EXISTS`，断点后重跑不会覆盖目标配置或文件访问数据。
4. 核对迁移账本恢复、原表和数据保持不变、`mcp_file_read_policy` 恰有一个默认配置且版本为 1，再启用新应用代码。

若执行失败，保留数据库现场和备份，重新核对 977 的结构后再次运行 `make migrate-up`；不得通过批量 `migrate down/up` 回滚。应用回退到旧版本时保留新增策略表和配置数据，旧版代码不读取该表；不要运行 977 的 down SQL，因为其中包含原文件工具的历史对象和数据。

## 验收边界

开发验证须覆盖空库应用迁移、旧 977 已执行库升级、重复执行与数据保留。生产账本和结构对齐由 Review 与独立 QA 后的运维执行并取证；开发不连接或改写 hp-server。目录策略不检测文件内容、改名副本或硬链接，也不对受控工具外的宿主机访问作安全承诺。
