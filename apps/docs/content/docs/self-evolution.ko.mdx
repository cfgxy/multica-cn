자기 진화는 워크스페이스의 프롬프트 거버넌스 워크벤치입니다. 워크스페이스 사이드바에서 **자기 진화**를 열면 [에이전트](/agents) 프롬프트의 버전 기록과 품질 측정을 확인하고, 고정 문제 은행으로 회귀 퀴즈를 실행하고, 입법 제안과 지식 미러를 통해 관찰 결과를 개선으로 전환할 수 있습니다.

페이지에는 8개의 탭이 있습니다. 개요, 품질, 버전, 퀴즈, Skill, 입법 제안, 일일 회고, 지식이며 기본으로 «품질» 탭이 열립니다.

## 개요

개요는 다른 탭의 핵심 판독값을 여섯 장의 카드로 모아 보여줍니다: 프롬프트 버전 활동(캐리어별 현재 버전과 최근 변경), 품질 측정값(시간 창 기준, 환경·벤더 장애 제외), 문제은행 결론(베이스라인과 현재 비교), 제안 풀(지표는 추후 연결), 지식 미러(등록된 디렉터리와 항목 수), Skill 관측(수와 누적 명시 호출).

## 품질

«품질» 탭은 한 에이전트 프롬프트의 실행 측정 대시보드입니다. 상단의 «대상» 선택기로 에이전트를 하나 고르고(대상은 현재 에이전트만 지원), «기간» 선택기로 통계 창을 조정합니다(기본 최근 30일).

대시보드는 7개 차원을 측정합니다.

| 차원 | 의미 |
|---|---|
| D1 주입 비용 / 실행 비용 | 실행마다 주입된 조립 프롬프트 토큰 중앙값. 실행 1회가 소비한 전체 토큰 중앙값. |
| D2 규율성 | 규율 점수 중앙값(100점 만점). 실행은 100점에서 시작해 기계적으로 판정 가능한 조항을 하나 어길 때마다 감점합니다. |
| D3 규칙 혼란도 | 조립 프롬프트의 모호성 점수. 런타임 형태(일반 멤버 실행 / 리더 태스크 실행)별로 평가하며 합산하거나 평균내지 않습니다. |
| D4 턴 실패율 | 에이전트가 받은 도구 결과 중 오류로 판정된 비율. |
| D5 재시도 | 한 번 넘는 시도가 필요했던 실행의 비율. |
| D6 프롬프트 귀인 실패 | 원인이 프롬프트를 가리키는 실패 횟수. 환경·공급자 귀인 실패는 제외됩니다. |
| D7 일회 통과율 | 검토 진입 후 재작업 없이 통과한 이슈 비율. |

«창 내 전체 버전»은 판독값을 프롬프트 버전별로 나눕니다. 타임라인에서 두 버전을 선택하면 차원별 차이를 비교할 수 있습니다. «버전 관리»를 누르면 «버전» 탭으로 이동합니다.

## 버전

«버전» 탭은 프롬프트 버전 수명 주기의 입구입니다. 지배하는 규칙은 하나뿐입니다. **유효한 변경은 모두 새 버전으로 추가되며 기록은 절대 다시 쓰이지 않습니다**.

버전 기록은 여섯 가지 프롬프트 대상 — 워크스페이스·프로젝트·스쿼드·에이전트·오토파일럿·스킬 — 을 포괄합니다. 이 페이지에는 내용 편집 UI가 없습니다. 버전은 «스냅샷»으로 대상의 현재 유효한 설정을 새 버전으로 기록하여 만듭니다. 내용을 바꾸려면 각 대상 자체의 관리 화면에서 하세요.

먼저 상단의 «대상 유형»으로 종류를 고르고, «대상»에서 구체적인 개체를 고르세요. «워크스페이스» 유형은 대상 선택이 필요 없습니다(이 워크스페이스 자신을 가리킴). 대상이 없으면 플레이스홀더만 표시됩니다.

### 스냅샷 만들기

1. 대상 유형과 대상을 고른 뒤 오른쪽 위의 «스냅샷»을 클릭하고 확인합니다.
2. 대상의 현재 유효한 설정이 새 버전으로 기록되고(소스 배지 «스냅샷»), 대상 자체의 내용은 변경되지 않습니다.
3. 스냅샷은 반복해서 만들 수 있습니다. 내용이 바뀌지 않았어도 다시 스냅샷할 수 있으며, 그때마다 새 버전이 추가됩니다.
4. 스냅샷의 변경 메모는 고정된 기본 문구로 기록됩니다.

<Callout type="warning">
스냅샷은 모든 버전 쓰기와 같은 게이트를 통과합니다. 대상의 현재 유효한 내용이 비어 있거나 200 KB를 초과하면 스냅샷이 거부되고(400), 자격 증명이 포함된 것으로 보이면 역시 거부됩니다(422). 이때 일치한 규칙·행 번호·마스킹된 샘플이 표시됩니다. 먼저 대상 자체의 관리 화면에서 해당 내용을 제거한 뒤 다시 스냅샷하세요.
</Callout>

### 활성화와 롤백

버전 목록은 최신 순으로 정렬됩니다. 각 행에는 소스 배지(베이스라인 / 편집 / 롤백 / 자동 스냅샷 / 스냅샷), 변경 메모, 생성일, 내용 지문 접두사, 품질 배지가 붙고, 최신 행에는 «최신» 배지가 표시됩니다.

임의의 과거 버전을 «이 버전으로 전환»으로 활성화하면 롤백이 됩니다. 그 내용이 새 최신 버전으로 복사되어 즉시 적용되며, 이전 버전들은 그대로 남습니다. 롤백으로 생긴 버전에는 «vN에서» 표시가 더해집니다. 이후 언제든 더 오래된 버전을 다시 활성화해 전환을 되돌릴 수 있습니다 — 기록은 추가만 하며, 모든 전환은 완전한 흔적을 남깁니다.

### 임의의 두 버전 비교

버전 칩 두 개를 클릭하면 두 내용의 차이 대화상자가 열립니다. 세 번째 칩을 클릭하면 오래된 선택이 교체되고, «선택 지우기»로 비교를 종료합니다.

### 품질 평가 결합

품질 평가는 각 실행을 그 실행이 가져간 프롬프트 버전에 묶습니다. 각 버전 행의 배지는 해당 버전이 처리한 실행 수를 보여주므로, 품질 변화가 어느 버전 이후에 일어났는지 바로 읽을 수 있습니다.

### 쓰기 권한

버전 읽기는 모든 멤버에게 열려 있습니다. «스냅샷»과 «이 버전으로 전환»은 워크스페이스 소유자 전용입니다(admin는 제외). 소유자가 아닌 멤버에게는 쓰기 컨트롤이 표시되지 않습니다.

## 퀴즈

«퀴즈» 탭은 하나의 고정 문제 은행을 모든 프롬프트 버전에 반복 실행해 «회귀 판독값»을 만듭니다. 한 버전을 기준(베이스라인)으로 삼아 현재 버전의 판독값 분포(중앙값, 사분위 범위)를 비교하고, 개선 / 유지 / 회귀 / 판독값 없음 판정을 내립니다.

- 판독값은 단일 점수가 아니라 분포입니다. 표본이 부족한 동안에는 비교하지 않습니다.
- 퀴즈는 프롬프트 버전 배포를 막지 않습니다. 품질이 어떻게 변했는지만 기록합니다.
- «문제 은행» 패널에서 고정 문제를 관리합니다. 문제 추가·편집·폐지가 가능하며, 문제 본문을 편집하면 새 개정 번호가 시작됩니다. 판독값은 같은 문면·같은 런타임과 모델의 결과 사이에서만 비교됩니다.
- 문제 본문은 자족적이어야 하며 운영 엔티티(이슈 키, ID, 링크)를 지목할 수 없습니다. 위반 본문은 서버가 거부합니다.
- 문제 은행 쓰기는 워크스페이스 소유자 전용입니다. «정답 키와 채점 항목»은 소유자만 볼 수 있고 측정 대상 실행에 전송되지 않습니다.

## Skill

«Skill» 탭은 [Skill](/skills)의 버전 기록과 관측된 사용 현황을 보여줍니다. 어느 에이전트에 할당되었는지, 명시적 호출 횟수, 버전별 토큰 소비 중앙값, 그리고 버전 판독값 대조(실행 토큰 중앙값·재시도율·일회 통과율을 사용 그룹 대조 그룹과 비교)입니다.

버전 간 차이는 관측값이며 skill이 변화를 일으켰다는 증거가 아닙니다. 차이는 양쪽 모두 유효한 실행 표본이 각각 5건 이상일 때만 표시됩니다.

과거 버전 복원도 추가 방식입니다. 소유자가 «이 버전 복원»을 클릭하면 그 내용이 새 버전이 되고 할당은 변하지 않습니다.

## 입법 제안

«입법 제안» 탭은 네 가지 프롬프트 캐리어(워크스페이스, 프로젝트, Squad, Agent)를 위한 조항 수준의 프롬프트 개선 초안을 관리합니다. 각 제안에는 대상 섹션과 변경 유형(조항 추가 / 삭제), 조항 최종 텍스트, 증거 앵커(이슈 번호 + 인용)를 첨부하며, 승인 요청 전에 내용 게이트 5 문답(계층 귀속, 존폐 판단, 비용 선언, 충돌 판정, 중복 확인)을 완료해야 합니다.

제안은 초안 → 승인 대기 → 승인됨 → 발효됨으로 흐릅니다. 게이트 미통과·반려된 제안도 기록으로 남으며, 재작업 후 다시 제출하거나 초안으로 복원할 수 있습니다. 출처 라벨은 수동 작성 / 일일 회고 자동 생성 / 병합을 구분합니다.

모든 멤버는 자신의 초안을 작성·편집·제출할 수 있습니다. 승인(일괄 승인 포함, 한 번에 최대 20건)·기각·초안 복원·발효는 워크스페이스 소유자 전용입니다. 승인 전에 샌드박스에서 캐리어 전체 diff를 미리 보고 명시적으로 확인해야 합니다. 발효는 입법 게이트를 다시 실행하고 통과한 경우에만 유효한 설정에 기록합니다.

## 일일 회고

«일일 회고» 탭은 기본 내장 작업입니다. 조회 기간 내 완료된 이슈의 실제 실행 내용을 읽어 프롬프트 개선 초안을 입법 제안으로 일괄 투입하며, 실행은 이슈 댓글을 남기지 않습니다.

설정 영역에는 «정기 실행 사용» 토글, «in_review 이슈도 스캔» 옵션, 조회 기간(일)이 있습니다. 저장하면 설정이 반영되고, «지금 실행»으로 수동 실행할 수 있습니다. 실행 기록에는 각 실행의 상태(성공 / 실패 / 실행 중), 창, 스캔 / 분석 / 신규 / 병합 / 중복 건너뜀 수와 오류가 표시됩니다.

LLM이 구성되지 않으면 실행 시 누락된 구성을 밝히는 실패 기록이 남습니다. 설정과 실행 기록 조회는 모든 멤버에게 열려 있습니다. 설정 변경과 지금 실행은 워크스페이스 소유자 전용입니다.

## 지식

«지식» 탭은 bd memories 디렉터리를 읽기 전용으로 미러링합니다. 연결된 데몬은 프로젝트 자체의 bd memories를 자동으로 발견하고, 로컬 디렉터리를 수동 추가할 수도 있습니다. 디렉터리를 등록하면 스캔을 실행할 수 있고(추가 / 갱신 / 삭제 건수 표시), 키나 내용으로 항목 미러를 검색할 수 있습니다.

미러 자체는 읽기 전용입니다. 유일한 쓰기 경로는 소유자가 대기 중인 항목을 «채택»해 지식 허브로 전송하는 것입니다. 등록·스캔·해제·채택은 워크스페이스 소유자 전용입니다.
