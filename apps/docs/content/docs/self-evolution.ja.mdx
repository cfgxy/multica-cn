自己進化はワークスペースのプロンプトガバナンス用ワークベンチです。ワークスペースのサイドバーで「自己進化」を開くと、[エージェント](/agents)のプロンプトに対するバージョン履歴と品質測定を確認し、固定問題バンクによる回帰クイズを実行し、立法提案とナレッジミラーを通じて観察結果を改善につなげられます。

ページには 8 つのタブがあります。概要・品質・バージョン・クイズ・Skill・立法提案・ふりかえり・ナレッジで、既定では「品質」が開きます。

## 概要

概要では、他のタブの主要な読み取り値を 6 枚のカードに集約して表示します: プロンプトバージョン活動（各キャリアの現在バージョンと最近の変更）、品質読み取り（期間窓ごと、環境・ベンダー障害は除外）、問題バンクの結論（ベースラインと現在の比較）、提案プール（指標は今後接続）、ナレッジミラー（登録ディレクトリとエントリ数）、Skill 観測（件数と累計明示的呼び出し）。

## 品質

「品質」タブは、あるエージェントのプロンプトに関する実行測定ダッシュボードです。上部の「対象」セレクターでエージェントを 1 つ選び（対象は現時点でエージェントのみ）、『期間』で統計窓を調整します（既定は直近 30 日）。

ダッシュボードは 7 つの次元を読み取ります。

| 次元 | 意味 |
|---|---|
| D1 注入コスト / 実行コスト | 実行ごとに注入された結合プロンプトのトークン中央値。実行 1 回が消費したトークン総量の中央値。 |
| D2 規律性 | 規律性スコアの中央値（100 点満点）。実行は 100 点から始まり、機械的に判定可能な条項を 1 つ破れるごとに減点されます。 |
| D3 ルール困惑度 | 結合プロンプトの曖昧性スコア。ランタイム形態（一般メンバー実行 / リーダータスク実行）ごとに評価され、合算や平均は行われません。 |
| D4 ターン失敗率 | エージェントが受け取ったツール結果のうちエラーと判定された割合。 |
| D5 リトライ | 複数回の試行を要した実行の割合。 |
| D6 プロンプト起因の失敗 | 原因がプロンプトを指す失敗の数。環境・プロバイダ起因の失敗は除外されます。 |
| D7 一発通過率 | レビュー入り後、手戻りなしで通過した課題の割合。 |

「期間内の全バージョン」は読み取り値をプロンプトバージョンごとに分解します。タイムライン上で 2 つのバージョンを選択すると、次元ごとに差分を比較できます。「バージョン管理」で「バージョン」タブへ移動します。

## バージョン

「バージョン」タブはプロンプトのバージョンライフサイクルへの入口です。支配的なルールは 1 つだけです。**有効な変更はすべて新バージョンとして追記され、履歴は書き換えられません**。

バージョン履歴は 6 種類のプロンプト対象 — ワークスペース・プロジェクト・スクワッド・エージェント・オートパイロット・スキル — をカバーします。このページには内容編集の UI がありません。バージョンは「スナップショット」で対象の現在有効な設定を新しいバージョンとして記録して作ります。内容を変更したいときは、各対象自体の管理画面で操作してください。

まず上部の「対象タイプ」で種類を選び、「対象」で具体的なオブジェクトを選びます。「ワークスペース」タイプは対象の選択が不要です（このワークスペース自身を指します）。対象未選択のときはプレースホルダーのみが表示されます。

### スナップショットの作成

1. 対象タイプと対象を選んだら、右上の「スナップショット」をクリックして確認します。
2. 対象の現在有効な設定が新しいバージョンとして記録され（ソースバッジ「スナップショット」）、対象自体の内容は変更されません。
3. スナップショットは繰り返し作成できます。内容が変わっていなくてももう一度スナップショットでき、そのたびに新しいバージョンが追記されます。
4. スナップショットの変更メモは、固定の既定文で記録されます。

<Callout type="warning">
スナップショットはすべてのバージョン書き込みと同じゲートを通ります。対象の現在有効な内容が空、または 200 KB を超える場合はスナップショットが拒否され（400）、認証情報が含まれている疑いがある場合も拒否されます（422）。その際は該当したルール・行番号・マスク済みサンプルが示されます。まず対象自体の管理画面で該当箇所を取り除いてから、スナップショットを作り直してください。
</Callout>

### 有効化とロールバック

バージョンリストは新しい順に並びます。各行にはソースバッジ（基線 / 編集 / ロールバック / 自動スナップショット / スナップショット）・変更メモ・作成日・内容フィンガープリントの接頭辞・品質バッジが付き、最新行には「最新」バッジが表示されます。

任意の過去バージョンを「このバージョンに切替」で有効化するとロールバックになります。その内容が新しい最新バージョンとしてコピーされ、即時に有効になります。旧バージョンはそのまま残り、ロールバック由来のバージョンには「vN から」と表示されます。後からさらに古いバージョンを有効化して切り替えを取り消すこともできます。履歴は追記のみで、切り替えはすべて完全な痕跡を残します。

### 任意の 2 バージョンの比較

バージョンのチップを 2 つクリックすると、両者の内容差分が開きます。3 つ目をクリックすると古い選択が置き換えられます。「選択をクリア」で比較を終えます。

### 品質評価との紐付け

品質評価は、各実行をそれが取得したプロンプトバージョンに紐付けます。各行のバッジはそのバージョンが処理した実行数を示すため、品質の変化がどのバージョンの後に起きたかを直接読み取れます。

### 書き込み権限

バージョンの閲覧はすべてのメンバーに開かれています。「スナップショット」と「このバージョンに切替」はワークスペースのオーナーのみです（admin は含まれません）。オーナー以外には書き込み操作が表示されません。

## クイズ

「クイズ」タブは、同一の固定問題バンクをすべてのプロンプトバージョンに対して繰り返し実行し、「回帰の読み取り値」を生成します。あるバージョンを基線として、現在バージョンの読み取り値分布（中央値・四分位距）を比較し、改善 / 横ばい / 回帰 / 読み取り値なしの判定を下します。

- 読み取り値は単一スコアではなく分布です。サンプルが満たない間は比較を行いません。
- クイズがプロンプトバージョンの公開を止めることはありません。品質の変化を記録するだけです。
- 「問題バンク」パネルで固定問題を管理します。問題の追加・編集・停用ができます。問題文の編集は新しい改訂番号を開始し、読み取り値は同じ問題文・同じランタイムとモデルの結果の間でのみ比較されます。
- 問題文は自己完結していなければならず、本番エンティティ（課題キー、ID、リンク）を指してはいけません。違反する本文はサーバーが拒否します。
- 問題バンクの書き込みはワークスペースのオーナーのみです。「解答キーと採点項目」はオーナーのみが閲覧でき、測定対象の実行には送信されません。

## Skill

「Skill」タブは [Skill](/skills) のバージョン履歴と観測された使用状況を表示します。どのエージェントに割り当てられているか、明示的な呼び出し回数、バージョンごとのトークン消費中央値、そしてバージョン読み取り値の対照（実行トークン中央値・リトライ率・一発通過率を、使用グループ対照グループで比較）です。

バージョン間の差は観測値であり、skill が変化を引き起こした証拠ではありません。差分の表示には両側でそれぞれ 5 件以上の有効な実行が必要です。

履歴バージョンの復元も追記方式です。オーナーが「このバージョンを復元」をクリックすると、その内容が新バージョンになります。割り当ては変わりません。

## 立法提案

「立法提案」タブは、4 つのプロンプトキャリア（ワークスペース・プロジェクト・Squad・Agent）向けの条項レベルのプロンプト改善草案を管理します。各提案には対象セクションと変更種別（条項の追加 / 削除）、条項の最終テキスト、証拠アンカー（Issue 番号 + 引用）を添え、承認に送る前に内容ゲートの 5 つの回答（レイヤー帰属、去留判断、コスト声明、競合裁定、重複チェック）を完了する必要があります。

提案は 下書き → 承認待ち → 承認済み → 発効済み と遷移します。ゲート不通過・却下された提案も記録として残り、手直しして再送信するか下書きに戻せます。ソースラベルは 手動 / 日次ふりかえりによる自動生成 / 統合 を区別します。

すべてのメンバーは自分の草案を作成・編集・送信できます。承認（一括承認を含み、1 回最大 20 件）・却下・下書きへの復元・発効はワークスペースのオーナーのみ実行できます。承認前にサンドボックスでキャリア全体の全文 diff をプレビューして明示的に確認する必要があります。発効は立法ゲートを再実行し、クリアした場合のみ有効な設定へ書き込まれます。

## ふりかえり

「ふりかえり」タブは組み込みの定期タスクです。参照ウィンドウ内の完了 Issue の実際の実行内容を読み、プロンプト改善草案を立法提案へ一括投入します。実行が Issue コメントを投稿することはありません。

設定エリアには「定期実行を有効化」トグル、「in_review の Issue も対象にする」オプション、参照ウィンドウ（日）があります。保存で設定が反映され、「今すぐ実行」で手動実行できます。実行履歴には各実行の状態（成功 / 失敗 / 実行中）、ウィンドウ、スキャン / 分析 / 新規 / 統合 / 重複スキップの件数とエラーが表示されます。

LLM が未設定の場合、実行は不足設定を示す失敗レコードを残します。設定と実行履歴の閲覧は全メンバーに開かれています。設定の変更と今すぐ実行はワークスペースのオーナーのみです。

## ナレッジ

「ナレッジ」タブは、bd memories ディレクトリを読み取り専用でミラーします。接続済みのデーモンはプロジェクト付属の bd memories を自動検出し、ローカルのディレクトリを手動追加することもできます。ディレクトリを登録するとスキャンを実行でき（追加 / 更新 / 削除の件数が表示されます）、キーまたは内容でエントリのミラーを検索できます。

ミラー自体は読み取り専用です。唯一の書き込み経路は、オーナーが未処理のエントリを「採用」してナレッジハブへ転送することです。登録・スキャン・解除・採用はワークスペースのオーナーのみ実行できます。

## 権限一覧

| 操作 | 権限 |
|---|---|
| 全タブと読み取り値の閲覧 | すべてのメンバー |
| スナップショットの作成・バージョンの有効化（ロールバック） | ワークスペースのオーナー |
| 問題の追加 / 編集 / 削除 | ワークスペースのオーナー |
| Skill バージョンの復元 | ワークスペースのオーナー |
| 提案の作成 / 編集 / 送信 / プレビュー / 手直し | すべてのメンバー（自分の草案のみ） |
| 提案の承認 / 却下 / 下書きへの復元 / 発効 | ワークスペースのオーナー |
| ふりかえりの設定変更 / 今すぐ実行 | ワークスペースのオーナー |
| ナレッジの登録 / スキャン / 解除 / 採用 | ワークスペースのオーナー |
